**تطبيق Astur التجريبي** (`com.astur.demo`) تطبيق أصلي صغير مهمته الوحيدة أن يمنح الأتمتة هدفًا ثابتًا ومتوقّعًا. وكل شاشة فيه تعرض قدرة واحدة — النقر، والتمرير، والتمرير الأفقي، والسحب، وإدخال النماذج، ورفع الملفات، و WebView الهجين — بمعرّفات اختبار ثابتة كي تبقى المحدِّدات موثوقة عبر التشغيلات والمنصات.

وهو التطبيق نفسه الذي تقوده المجموعات القابلة للتشغيل، فاللقطات أدناه تقابل واحدةً بواحدة ملفات الاختبار في قالب [astur-boilerplate](https://github.com/Astur-mobile/astur-boilerplate) (وفي مجلد [`examples/`](https://github.com/Astur-mobile/astur-boilerplate) داخل المستودع).

## من أين تحصل عليه

تُشحن البنى مع القالب المبدئي وفي مجلد `assets/` بهذا المستودع:

- **‏Android:** `assets/astur.demo.android.apk`
- **‏Android (‏Flutter):** `assets/astur.demo.android_flutter.apk`
- **محاكي iOS:** `assets/astur.demo.ios.simulator.zip` (فُكّه إلى `assets/Astur.app`)
- **محاكي iOS (‏Flutter):** `assets/astur.demo.ios.simulator_flutter.zip` (فُكّه إلى `assets/Runner.app`)
- **جهاز iOS حقيقي:** `assets/astur.demo.ios.ipa`

## أهداف التشغيل

تعمل ملفات الاختبار نفسها على أربعة أهداف. ويثبّت Astur التطبيق التجريبي في التشغيل الأول ويثبّت وكيله تلقائيًا، فالشرط الوحيد هو جهاز مرئي.

| الهدف | يظهر عبر | ما تحتاجه |
| --- | --- | --- |
| **محاكي Android** | `adb devices` (مثل `emulator-5554`) | جهاز افتراضي مُقلع. ولا شيء غير ذلك — فـ Astur يثبّت حزمة APK ووكيله. |
| **جهاز Android حقيقي** | `adb devices` | تفعيل تنقيح USB والموافقة على الجهاز. ومسار التثبيت التلقائي نفسه. |
| **محاكي iOS** | `xcrun simctl list devices booted` | محاكي مُقلع وملف `Astur.app` بعد فكّه. |
| **جهاز iOS حقيقي** | `xcrun devicectl list devices` | جهاز موثوق بوضع المطوّر، وملف `.ipa`، وضبط `ASTUR_IOS_DEVELOPMENT_TEAM` كي يمكن توقيع وكيل XCUITest. |

جرّبه عبر الـ Inspector دون كتابة أي اختبار:

```bash
# محاكي Android
npx astur-mobile codegen --android --device emulator-5554 \
  --app ./assets/astur.demo.android.apk --app-id com.astur.demo

# محاكي iOS
npx astur-mobile codegen --ios --simulator \
  --app ./assets/Astur.app --app-id com.astur.demo
```

أو شغّل مجموعة الميزات كاملةً من قالب [astur-boilerplate](https://github.com/Astur-mobile/astur-boilerplate):

```bash
npx astur-mobile test --config config/android/playwright.config.ts
```

:::note[التحكم في DOM داخل WebView]
تقود `device.webContext()` شجرة DOM في WebView على **‏Android و iOS (المحاكي والأجهزة الحقيقية)**.

- **‏Android** — يفعّل التطبيق تنقيح WebView (`WebView.setWebContentsDebuggingEnabled(true)`)، فيكشف مقبس Chrome DevTools Protocol. وتُشحن حزمة العرض وهي مفعّلة.
- **‏iOS** — يضبط التطبيق `WKWebView.isInspectable = true` (‏iOS 16.4 فأعلى) ويكون `ios-webkit-debug-proxy` (‏1.9 فأعلى) مثبّتًا (`brew install ios-webkit-debug-proxy`). ويجسر Astur الـ Web Inspector في المحاكي تلقائيًا.

وتبقى تجهيزة `webview()` (‏`web.page`) بصفحة Playwright خاصة بـ Android؛ وعلى iOS استخدم `device.webContext()` أو المحدِّدات الأصلية.
:::
