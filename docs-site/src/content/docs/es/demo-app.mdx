La **app de demostración de Astur** (`com.astur.demo`) es una pequeña app nativa cuyo único cometido es dar a la automatización un objetivo estable y predecible. Cada pantalla demuestra una capacidad — toque, scroll, deslizamiento, arrastre, entrada de formularios, subida de archivos y WebView híbrida — con identificadores de test fijos, para que los localizadores sigan siendo fiables entre ejecuciones y plataformas.

Es la misma app que usan las suites ejecutables, así que las capturas de abajo se corresponden una a una con los specs del starter [astur-boilerplate](https://github.com/Astur-mobile/astur-boilerplate) (y con [`examples/`](https://github.com/Astur-mobile/astur-boilerplate) dentro del repositorio).

## De dónde sacarla

Las compilaciones vienen con el boilerplate y en `assets/` de este repositorio:

- **Android:** `assets/astur.demo.android.apk`
- **Android (Flutter):** `assets/astur.demo.android_flutter.apk`
- **Simulador de iOS:** `assets/astur.demo.ios.simulator.zip` (descomprime en `assets/Astur.app`)
- **Simulador de iOS (Flutter):** `assets/astur.demo.ios.simulator_flutter.zip` (descomprime en `assets/Runner.app`)
- **Dispositivo iOS real:** `assets/astur.demo.ios.ipa`

## Dónde se puede ejecutar

Los mismos specs corren en cuatro destinos. Astur instala la app de demostración en la primera ejecución e instala su propio agente automáticamente, así que el único requisito es que haya un dispositivo visible.

| Destino | Se ve con | Qué necesitas |
| --- | --- | --- |
| **Emulador de Android** | `adb devices` (p. ej. `emulator-5554`) | Un AVD arrancado. Nada más: Astur instala el APK y su agente. |
| **Dispositivo Android real** | `adb devices` | Depuración USB activada y el dispositivo autorizado. Misma instalación automática. |
| **Simulador de iOS** | `xcrun simctl list devices booted` | Un simulador arrancado y `Astur.app` descomprimido. |
| **Dispositivo iOS real** | `xcrun devicectl list devices` | Un dispositivo de confianza con Modo Desarrollador, el `.ipa`, y `ASTUR_IOS_DEVELOPMENT_TEAM` definido para poder firmar el agente XCUITest. |

Pruébala desde el Inspector sin escribir ni un test:

```bash
# Emulador de Android
npx astur-mobile codegen --android --device emulator-5554 \
  --app ./assets/astur.demo.android.apk --app-id com.astur.demo

# Simulador de iOS
npx astur-mobile codegen --ios --simulator \
  --app ./assets/Astur.app --app-id com.astur.demo
```

O lanza la suite completa desde el starter [astur-boilerplate](https://github.com/Astur-mobile/astur-boilerplate):

```bash
npx astur-mobile test --config config/android/playwright.config.ts
```

:::note[Control del DOM en WebViews]
`device.webContext()` maneja el DOM de las WebViews en **Android y iOS (simulador y dispositivos reales)**.

- **Android** — la app activa la depuración de WebView (`WebView.setWebContentsDebuggingEnabled(true)`), lo que expone el socket del Chrome DevTools Protocol. El APK de demostración ya viene con esto activado.
- **iOS** — la app pone `WKWebView.isInspectable = true` (iOS 16.4+) y tienes `ios-webkit-debug-proxy` (v1.9+) instalado (`brew install ios-webkit-debug-proxy`). Astur conecta el Web Inspector del simulador automáticamente.

El fixture `webview()` basado en Page de Playwright (`web.page`) sigue siendo solo para Android; en iOS usa `device.webContext()` o localizadores nativos.
:::
