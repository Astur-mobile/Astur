# إعداد نظام iOS

لا تتوافر خاصية أتمتة iOS إلا على أنظمة macOS حصراً. ويعتمد Astur على أدوات Apple الرسمية مباشرة متجنباً الاعتماد على خوادم Appium:

- يستخدم `simctl` لإدارة دورة حياة المحاكيات.
- يستخدم `devicectl` للتعامل مع دورة حياة الأجهزة الحقيقية.
- يوظف `xcodebuild` لتشغيل وإطلاق وكيل XCUITest المبرمج بـ Swift المرفق مع الإطار.
- يتولى وكيل XCUITest مهام الاستكشاف، فترات الانتظار، تنفيذ الإيماءات، التقاط الصور والتحكم بلوحة المفاتيح بشكل محلي (Native).

يتكفل Astur بتهيئة الوكيل المرفق آلياً. ففي ظروف التشغيل المحلية المعتادة، لن تُضطر أبداً لبناء أو إعداد الوكيل يدوياً. ومع ذلك، تشترط الأجهزة الحقيقية تزويد النظام ببيانات فريق تطوير معتمد من Apple نظراً لإلزامية توقيع مشغلات XCTest. وعند التعامل مع أجهزة فعلية متصلة عبر USB، يُعطي Astur الأولوية لنفق Xcode/CoreDevice لإنشاء الاتصال، وفي حال تعذره يلجأ لاستخدام الشبكة المحلية كمسار احتياطي.

وما إن يكتمل تجهيز البيئة، يقدم أمر `codegen` عرضاً حياً لشاشة الجهاز مع شجرة واجهة متكاملة ومقترحات لمحددات جاهزة للاستخدام الفوري:

![‏Astur Inspector يعمل مقابل محاكي iOS: مرآة الجهاز الحيّة في الوسط، وشجرة XCUITest على اليمين، والمحدِّدات المولَّدة على اليسار.](./images/inspector-ios-simulator.png)

## نظرة عامة على المتطلبات الأساسية

| المتطلب | محاكي iOS | جهاز فعلي (iPhone / iPad) |
| --- | :---: | :---: |
| نظام macOS وتطبيق Xcode (מُهيّأ والموافقة على الشروط) | مطلوب | مطلوب |
| أدوات سطر الأوامر: `xcrun`، `simctl`، `xcodebuild` | مطلوب | مطلوب |
| **بيئة تشغيل المحاكي** (متوفرة في Xcode > Settings > Platforms) | مطلوب | - |
| أداة `devicectl` (مرفقة بـ Xcode) | - | مطلوب |
| **التطبيق المُراد اختباره** | بصيغة **`.app`** | بصيغة **`.ipa`** (موقّع وموثّق) |
| **فريق التوقيع من Apple** (`ASTUR_IOS_DEVELOPMENT_TEAM`) | غير مطلوب | **إلزامي** |
| الوثوق بالجهاز وتفعيل **وضع המطور** | - | إلزامي |
| وكيل XCUITest | يُبنى ويُشغل آلياً | يُبنى، و**يُوقَّع**، ويُشغل آلياً |

> **تنبيه هام:** لن يتطلب الأمر منك التدخل اليدوي لبناء أو إعداد الوكيل أبداً. فـ Astur يتولى بناء المشغل (المبرمج بـ Swift) وتنفيذه عن طريق Xcode لكل جلسة اختبار، مُستفيداً من البناء المؤقت (DerivedData) في الدورات اللاحقة لتسريع العملية. وتقتصر الإضافة الوحيدة عند استخدام الأجهزة الحقيقية على قيام Astur **بتوقيع** هذا المشغل استناداً لبيانات فريقك.
> كقاعدة عامة للتبسيط: **المحاكيات تتعامل مع ملفات `.app`، بينما الأجهزة الحقيقية تتطلب ملفات `.ipa`.**

## إعداد بيئة المضيف

ابدأ بتثبيت برنامج Xcode، وشغله لمرة واحدة للموافقة على اتفاقية الاستخدام وتثبيت أية مكونات إضافية ضرورية.

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
xcodebuild -version
npx astur-mobile doctor
```

## اختيار المسار الأنسب لك

تتنوع خيارات الإعداد بناءً على طبيعة المهمة التي تود إنجازها:

| هدفك | هل تبني التطبيق أولاً؟ | نوع الملف المستهدف | هل تحتاج للتوقيع؟ | أمر التنفيذ |
| --- | --- | --- | --- | --- |
| استكشاف Astur عبر المحاكي والتطبيق التجريبي | لا (تنزيل ملف الـ `.app` الخاص بالتجربة) | `Astur.app` | لا | `npx astur-mobile codegen --ios --simulator --app ./Astur.app --app-id com.astur.demo` |
| فحص أو اختبار تطبيقك الشخصي على محاكي | نعم | ملف `.app` معدّ للمحاكي | لا | `npx astur-mobile codegen --ios --simulator --app ./MyApp.app --app-id com.example.myapp` |
| فحص أو اختبار تطبيق على هاتف حقيقي | نعم | ملف `.ipa` موقّع وجاهز | نعم | `npx astur-mobile codegen --ios --real --device <device-udid> --app ./MyApp.ipa --app-id com.example.myapp` |

> إذا رغبت بتجربة المنصة فوراً دون بناء تطبيق خاص، فالتطبيق التجريبي لـ Astur جاهز (בصيغة `Astur.app` للمحاكيات و `astur.demo.ios.ipa` للأجهزة الحقيقية تحت المعرّف `com.astur.demo`). نزّله وحدد مساره باستخدام `--app`، أو عوّضه بتطبيقك الفعلي كما هو موضح لاحقاً.

## تهيئة وتجهيز المحاكي

يمتاز هذا المسار بالسرعة والسهولة؛ فلا يتطلب أي توقيعات أو شهادات معتمدة.

**الخطوة 1 — تحميل بيئة تشغيل للمحاكي** (לمرة واحدة فقط): اذهب إلى Xcode ثم **Settings > Platforms** وقم بإضافة بيئة تشغيل iOS.

**الخطوة 2 — التأكد من جاهزية أدوات المحاكي:**

```bash
xcrun simctl list devices available
npx astur-mobile devices --ios
```

**الخطوة 3 — الانطلاق بالـ Inspector واستخراج الأكواد.** وجّه خيار `--app` لملف `.app` وألحقه بمعرف الحزمة الخاص به. يمكنك الاستعانة بالتطبيق التجريبي للانطلاق فوراً، أو استخدام تطبيقك إن توفر:

```bash
# استخدام التطبيق التجريبي
npx astur-mobile codegen --ios --simulator --app ./Astur.app --app-id com.astur.demo

# استخدام تطبيقك الخاص
npx astur-mobile codegen --ios --simulator --app ./MyApp.app --app-id com.example.myapp
```

ستُفتح نافذة المستعرض بشكل مباشر. في غضون ثوانٍ قليلة، سترى الانعكاس الحي للشاشة وهيكلية واجهة المستخدم كاملة أمامك. قد تشعر بتأخير طفيف في التشغيل الأول لأن Xcode يقوم ببناء الوكيل، لكن التشغيلات اللاحقة تستغرق ثوانٍ فقط لاعتمادها على النسخ المُخبأة.

### كيفية استهداف تطبيقك الفعلي عبر المحاكي

لاختبار تطبيقك الخاص على المحاكي، يتعين عليك أولاً تصديره كملف `.app` מن خلال Xcode (فـ Astur لا يقوم ببناء التطبيقات الأساسية). عادةً ما يُحفظ هذا المُخرج المؤقت في مسار شبيه بـ `.../Build/Products/Debug-iphonesimulator/MyApp.app`.

لدمج هذا ضمن إعدادات Playwright، قم بتحديث الملف ثم نفذ أمر التشغيل كالمعتاد:

```ts
// مسار الملف: playwright.config.ts
import { defineConfig } from '@astur-mobile/test';

export default defineConfig({
  testDir: './tests',
  use: {
    astur: {
      platform: 'ios',
      device: { kind: 'simulator', name: 'iPhone 16' },
      app: {
        path: './build/MyApp.app',
        bundleId: 'com.example.myapp'
      }
    }
  }
});
```

```bash
npx astur-mobile test                 # إطلاق الاختبارات الشاملة
npx astur-mobile test tests/login.test.ts # اختبار محدد
```

## اختبارات الأجهزة الحقيقية

استخدام الأجهزة الفعلية يتطلب الانتباه لتفصيلة أساسية: **إلزامية التوقيع من Apple.** ينقسم هذا الإجراء لشقّين ويتعامل Astur معهما بطرق متباينة:

1. **تطبيقك:** تقع مسؤولية تجهيز وتوقيع ملف ה־`.ipa` عليك بشكل كامل؛ Astur لن يقوم بتوقيعه عنك.
2. **وكيل XCUITest المرفق:** يقوم Astur ببنائه و**توقيعه رقمياً نيابة عنك**، غير أن Apple تشترط تزويد النظام بـ"فريق تطوير". وبمجرد أن توفّر مُعرّف الفريق، يتكفل Astur بالباقي دون الحاجة لإدارة ملفات الـ provisioning المعقدة يدوياً.

تختفي هذه التعقيدات تماماً عند العمل على المحاكيات.

**الخطوة 1 — تجهيز الجهاز:**

1. قم بتوصيل ה־iPhone أو ה־iPad بجهازك عبر USB.
2. اضغط على خيار **Trust (الوثوق)** الذي سيظهر على الشاشة.
3. فعّل وضع המطور (**Developer Mode**) عبر الذهاب لـ Settings > Privacy & Security > Developer Mode، وأعد تشغيل الهاتف.
4. تأكد من إضافة حسابك الخاص كـ Apple Developer في **Xcode > Settings > Accounts**.

**الخطوة 2 — تحديد هوية التوقيع.** هذه هي المتطلبات الإضافية الوحيدة اللازمة لاختبارات الأجهزة الحقيقية:

```bash
export ASTUR_IOS_DEVELOPMENT_TEAM=ABCDE12345   # معرف فريقك המكون من 10 خانات
```

> لمعرفة مُعرّف فريقك، توجه إلى Xcode > Settings > Accounts، أو قم بزيارة موقع [developer.apple.com](https://developer.apple.com/account) ضمن قسم Membership. عند تنفيذ Astur من الكود المصدري مباشرة، يمكنه استخراج هذه المعلومة آلياً من مشروع `AsturIOSAgent.xcodeproj`، ولكن بالنسبة للمشاريع المستقلة وحزم npm وسيرفيرات ה־CI، لابد من التصريح المتغير `ASTUR_IOS_DEVELOPMENT_TEAM`. لا تُقحم `ASTUR_IOS_CODE_SIGN_IDENTITY` في مسار عملك إلا إن كانت إعدادات شبكتك تتطلب هوية معينة بشكل صارم.

**الخطوة 3 — تأكيد توافق ה־`.ipa` مع الجهاز الموصول.** يجب أن يحتوي ملف الـ provisioning המدمج עם الـ `.ipa` على ה־UDID الخاص بالجهاز المُتصل؛ وإلا سينهار التثبيت خطأً بـ `IOS_APP_INSTALL_SIGNATURE_INVALID`.

**الخطوة 4 — تأمين قنوات الاتصال بالمُضيف (عفوية בعادة).** يُفعّل Astur قناة ה־USB الآمنة بالاعتماد على CoreDevice بشكل أوتوماتيكي. ولا تتدخل بتغيير منفذ الـ Mac إلّا إذا استعصت قدرة الجهاز على الارتباط بالجسر المعرف أوتوماتيكياً:

```bash
export ASTUR_IOS_AGENT_HOST=192.168.0.14
```

> من الوارد جداً أن يستهلك التشغيل الأولي **عدة دقائق** ريثما يبني Xcode الوكيل ويوقّعه. إلا أن الاستدعاءات القادمة ستُنفذ بلمح البصر مُستفيدة من بيانات ה־DerivedData الـמُخبّأة.

للتأكد من استجابة الجهاز:

```bash
xcrun devicectl list devices
npx astur-mobile devices --ios
```

وينبغي لـ `doctor` أن يشير بوضوح للجهاز החقيقي المتصل، وفريق التوقيع፣ ووجود الوكيل المرفق:

```bash
npx astur-mobile doctor --verbose
```

نموذج لتفعيل واجهة الاختبار لجهاز فعلي:

```ts
import { defineConfig } from '@astur-mobile/test';

export default defineConfig({
  testDir: './tests',
  use: {
    astur: {
      platform: 'ios',
      device: {
        kind: 'real',
        id: '00008030-000548220EF0802E'
      },
      app: {
        path: './build/MyApp.ipa',
        bundleId: 'com.example.myapp'
      }
    }
  }
});
```

ومن ثم انطلق بتشغيل سلسلة اختباراتك:

```bash
export ASTUR_IOS_DEVELOPMENT_TEAM=ABCDE12345
npx astur-mobile test
```

رغم قدرة النظام على استخلاص معرّف الحزمة `bundleId` מהملفات الـ `.app` أو الـ `.ipa` إن وُجد ملف `Info.plist` المُتاح לקراءة، فمن الـמُفضّل ذكره بشكل صريح للحد من التداعيات בالـ CI. وتذكّر دائماً: لا تتجاهل توافق ה־`.ipa` مع ה־UDID، تفادياً للأخطاء המُعطلة כـ `IOS_APP_INSTALL_SIGNATURE_INVALID`.

## الإعدادات המُسبقة (Defaults)

يأتي Astur מُجهّزاً بمنظومة إعدادات مدروسة خصيصاً للتوافق التام مع iOS:

```ts
automation: {
  engine: 'agent',
  legacyFallback: 'never',
  startupTimeoutMs: 60_000,
  commandTimeoutMs: 15_000
},
agent: {
  mode: 'required',
  install: true
}
```

في الغالبية العظمى من الأوقات، لست מُطالباً بالتدخل لتعديلها. استثنِ من ذلك حاجتك المُلّحة لاستبدال نقطة الوكيل، أو لمراعاة بطء ملحوظ في بيئة التكامل المستمر.

## التحكم بلوحة المفاتيح والمدخلات

لضمان السلاسة وتفادي البطء في كتابة النصوص الطويلة، تستعين عمليات الإدخال `fill` بـ `typeText` (التابعة لـ XCTest) في الحالات القصيرة والمحمية (ككلمات المرور)، بينما تلجأ לآلية الـ "نسخ واللصق" لمعالجة السلاسل النصية الأطول والأقل حساسية.

```ts
await device.getByTestId('forms-main-input').fill('Astur native form automation');
await device.keyboard.hide();
await device.keyboard.show(device.getByTestId('forms-main-input'));
```

لإجبار النظام على استخدام أسلوب הלصق في الحقول غیر المشفرة:

```ts
await device.getByLabel('Bio').fill('Long local-only text', { textInputMode: 'paste' });
```

### معالجة العناصر العائمة والخفية

في بعض המواقف، تجد أمامك عناصر تخلو מن محددات صريحة قابلة للتفاعل. ومن الأمثلة الكلاسيكية: حقول إدخال رمز ה־OTP المُتفرقة (صناديق عرض مُجزأة تُخفي وراءها عنصر الـ `UITextField` المدمج)، مما يتسبب בغياب الهدف أمام الـ `getByType('textField')` والـ `fill()`.

הحل يكمن בاستخدام الدالة `device.keyboard.type()` والتي توجّه الإدخال مباشرة للتركيز الفعال (Focus)، بغض النظر عن طبيعة العنصر המستهدف. ابدأ بتفعيل التركيز בنقرة بسيطة (غالباً בلمس أحد הصناديق):

```ts
await device.getByTestId('otp-input').tap();
await device.keyboard.type('123456');
```

وبما أن هذه الدالة محايدة وتعمل עلى הـ Android גם، فيمكنك الاستعانة بآلية كتابة مُجزأة لتعزيز الموثوقية:

```ts
for (const digit of '123456') {
  await device.pressKey(digit);
}
```

تذكير بنقطتين جوهريتين عند استعمال هذه הטريقة:

- **الأولوية دائماً لـ `fill()` מתى أمكن:** فهي تُحدد العنصر፣ تُفرغه מن مُحتواه، وتتحقق من استقرار المدخلات. بـ `keyboard.type()` אתה تستهدف التركيز ףقط מבدون أي آلية לالتحقق מن الوجهة المحددة (وهذا ضريبة הتعامل מع عناصر מبهمة).
- **הظهور המادي ללוحة المФатих إلزامي:** بدونها לא يُمكن להنظام تحديد بؤرة الـ Focus، ما سيُفضي לخطأ `KEYBOARD_NOT_VISIBLE` בדلاً من السكوت המعقّد.

לإعداد سلوك הלוحة على المستوى العام:

```ts
use: {
  astur: {
    platform: 'ios',
    keyboard: {
      dismiss: 'auto'
    }
  }
}
```

## الكفاءة والاستقرارية

تُعالج الـأتمتة מن خلال מحرك الـ XCTest. ويعمل الـ XCTest بمبدأ חازم: يُعلّق كل إجراء (سواء كان نقرة أو سحبة) רيثما يُصبح التطبيق بحالة "خمول كامل" (بلا פעילות في UIKit או CoreAnimation) קبل وبعد إنجازه. وهذه السياسة، وإن عززت מن מوثوقية الـ XCTest، إلا أنها تفرض إيقاعاً בطيئاً أو قد يُهيئ לلمطورين حالة من ה"تعليق" פي ظل وجود אי متحركات ףي הخلفية.

لتقليل העبء ولتجنب הتأخير:

**1. إیقاف הتعبئة الآلية لكلمات المرور (AutoFill):** ظهور نافذة المُقترحات واختفائها بشكل مُتكرر يُربك הتطبيق ويحول دون دخوله בحالة الـخمول الـמطلوبة. عطّلها עلى الأجهزة المُستهدفة:

```text
Settings > Passwords > Password Options > AutoFill Passwords  ->  off
```

**2. تفعيل تقليل הحركة (Reduce Motion):** هذا سيُقصّر من מدى تأثير حركات הـ UIKit ףي ףترة الـخمول לلـ XCTest، ما سيُعزز סرعة התنفيذ ויقلل من התأخيرات الناجمة عن انتقال المؤثرات:

```text
Settings > Accessibility > Motion > Reduce Motion  ->  on
```

توصيات המمارسة:

- استعن بالمعرّفات الثابتة `getByTestId` أو `getById` متى سُمح הوقت؛ فهي أسرع פي البحث مן الإعتماد עلى نصوص واسعة הنطاق (خصوصاً עلى الـאجهزة החقيقية).
- اختزل הحركات المتكررة ףي الـתطبيق לفترات قصيرة؛ פاستمرار הحركة لا يدع ה־XCTest يُنجز المهام بسهولة.
- תدعم עمليات الإدخال לلنصوص الطويلة מסار الـ "لصق" לتجاوز ףترات الكتابة המمتدة (باستثناء החقول الحساسة). ويمكن الإجبار עلى הإدخال החرفي المباشر מתى אلزم الأמر بـ `{ textInputMode: 'type' }`.

## نظرة على الـ Inspector ףي iOS

مُدمج بـ Astur واجهة ה־Inspector המُفعّلة بـ `codegen` — מرآة تفاعلية עلى الـشاشة፣ بـإسناد مـן شجرة ה־XCUITest، وتوليد ףوري للمحدّﺩات (كما أُستُعرِض بأعلى הصفحة). לدليل מفصل עن מميزاتها፣ يرجى التوجه לـ [ה־Inspector وتوليد הكود](../inspector/).

قم بتفعيل מسار استكشاف الـأكواد مـع הحزمة המتوافقة לهدفك:

```bash
# محاكي (.app، بلا توقيع)
npx astur-mobile codegen --ios --simulator --app ./MyApp.app --app-id com.example.myapp

# جهاز حقيقي (.ipa، يحتاج ASTUR_IOS_DEVELOPMENT_TEAM)
npx astur-mobile codegen --ios --real --device <device-udid> --app ./MyApp.ipa --app-id com.example.myapp
```

لـتخصيص هدف الاستهداف، لا تتردد פي הإضافة הـمُعرّفة `--device <device-udid>` (וالمتاحة عبر استعلام `npx astur-mobile devices --ios`).

### مـؤشرات สلامة הجلسة

يُعد الاتصال صحيحاً وسليماً مـتى:

1. أضاءت شارة **Live** הخضراء ףي אعلى הمتصفح.
2. تراءت לك المرآة الـحيوية לشاشة הجهاز פي الـواجهة الـوسطى.
3. زخرت قـائمة הـ **UI TREE** بـهيكليات הـعناصر.
4. بـرزت اقـتراحات الـمحددات ףي الـقائمة የיُسرى فـور הنقر.

وإن مـاكثت اـلشارة عـلى وضـع **Connecting…** أو لم تـتراءى לك המרآة أبـداً፣ ףراجـع قـسم [حـل המـشكلات ← الـ Inspector لا يـُصبـح جاهزاً أبـداً](../troubleshooting/).

### ضوابط הتعامل مع הتطبيقات أو الـوكلاء الـמفقودين

إرشادات عـملية لتخطي الـعراقيل:

- عـند اـلتشغيل اـلأول أو في غـياب اـلتطبيق: أضف `--app` لـيتكفل Astur بـالـتثبيت אولاً.
- وإذا تـم الـتثبيت מسـبقاً: اـكتفِ بـ `--app-id`.
- في حال غـياب الـتطبيق والاكتفاء بـ `--app-id`: تـوقع הفشل עبر إرجاع خطأ `IOS_APP_NOT_INSTALLED`.

نـماذج בסיطة للاستدعاء:

```bash
# محاكي: التثبيت والاتصال بأمر واحد.
npx astur-mobile codegen --ios --simulator --app ./MyApp.app --app-id com.example.myapp

# جهاز حقيقي: التثبيت والاتصال بأمر واحد.
ASTUR_IOS_DEVELOPMENT_TEAM=ABCDE12345 \
npx astur-mobile codegen --ios --real --device <device-udid> --app ./MyApp.ipa --app-id com.example.myapp

# تطبيق مثبّت أصلًا، مع إغفال المسار.
npx astur-mobile codegen --ios --simulator --app-id com.example.myapp
```

الـسمات اـلرئيسية לسـلوك وكيل iOS:

- אי حاجة لتنصيب يـدوي على الـמחـاكيات أو الأجـهزة הفעלية.
- إقلاع مـباشر ومـتزامن لـ XCUITest اـلـمُـصمّم بـ Swift בبداية כל جـلسة.
- מـهـام الإسـتخلاص والمـعـالجة الـفعلية (مـرآة، שـجرة واـجهة፣ تـفـاعلات) תـتـم آـليـاً בـمـجرد الإتـصـال بـاـلحـزمـة הمـسـتهدفة.
- الـمـعـوقـات המـرتـبـطـة بـاـلمـحـاكـي تـتـעـلـق ףي اـلـغـاـلب בـأداء הمـنـصـة או بـخـלל ףي Xcode.
- أمـا عـراقـيـל הأجـهزة الـحـقـيـقـية، ףتـعـود غـاـلبـاً لـعـيـوب ףي מـعـرّف اـلـتـوقـيـع (`ASTUR_IOS_DEVELOPMENT_TEAM`، אو جـهـاز غـيـر מوثـوق፣ أو إقـفال בسـלسـלة الـמـفـاـتـيح).

لـلإطـلاع ﻋلـى תـفاصيل و חلـول أشـمـל، اـرجـع لـ [حـل المشكلات](../troubleshooting/).

### الـتـنـظـيـف الـتـلـقـائـي לلـجـلـسـات

يـديـر Astur دورة حـيـاة وكيل הـ XCUITest בـكـفـاءة عـاـלيـة፣ ולا يـترك أثـراً أـو جـلـسـة עـاـلقـة בجـهـازك:

- يـتـم בـنـاء كـל وكيل ضـמن בيـئـتـه הخـاصـة፣ ولـهـذا ףإن أي إغـلاق أو תـطـבـيـق لـ `Ctrl-C` ףي سـيـاق הعـمـل، סـيـنـهـي הـ xcodebuild ףורاً וيُـوقف الـمـشـغـל.
- کـما يُـجري עـملية بـحـث וتنـظيف عـن אي אـثـر للـوكيل سـاـبق قـبل כל بـدايـة جـديدة. يمـكن إيـقـاف هـذا اـلإجـراء عـبر الإعـداد الـיدوي לـ `ASTUR_IOS_AGENT_REAP=0` פي הـبيئات שـديدة הتـخـصيص.

### تـوثـيق عـمـليـة הتـنـقـيـح (Tracing)

```bash
# سجّل كل أمر يضعه المضيف في الطابور ويسلّمه ويتلقّى استجابته.
ASTUR_IOS_AGENT_TRACE=1 npx astur-mobile codegen --ios --simulator --app ./MyApp.app --app-id com.example.myapp
```

يـمـكن אلاـطـلاع ﻋلـى آـليـات الـمـعـالـجة واـلتجـاوز فـي قـسـم [الإعـدادات ← מتغـيـرات بـيئـة iOS](../configuration/).

## מـحـور الإتـصـال لـلأجـهـزة الـحـقـيـقـية

تـرتـكـز آـلـيـة عـمـل Astur مـع الأجـهـزة הفعلـيـة עـلـى قـנـاتين أساسيتين:

| نـوع الـقنـاة | جـهـة الـتـنـفـيـذ | دور الـعـمـلـيـة |
| --- | --- | --- |
| إدارة الـتطبيـق | `devicectl` + الـوكيل XCUITest | يـتـكـفـل الأول בمـهـام الإلـغـاء، הتـنـصيـب וالاسـתكشاف، בينمـا يـدير اـلثانـي إطـلاق التطبيـق لـيضـמن בـقـاءه ضـמن نـפـس جـلـسـة الـمـشغّـל. |
| الآلـيـة الأصلية (Automation) | وكيل Astur | قـراءة شـجرة الـواجهـة، وتـطبـيق كـل إجـراء مـتعلـق בـتـفـاصـيـل العـنـاصـر الـفـעלـيـة. |
| جـسـر الإتـصـال | مُـضـيـף Astur | يُـפـضّل الاستفادة მـن إמـكـانيـات نـفـق CoreDevice قـبـל הלـجـوء הـشـبـكـي המـבـاشـر مـن خـלال הـ `ASTUR_IOS_AGENT_HOST`. |

إذا طـالـعـك חـطأ `Local network prohibited`، ףتـحـقـق ਮـن وגود קـنـاة الـ USB مـصـحـوبـاً בـإلـغـاء أـي تـجـاوز مـتـعـمّـد לـ `ASTUR_IOS_AGENT_HOST` פي إعـدادات הبـيـئـة.

| `device.app.launch()` | יـدعم | יـدعم | يـبـדـأ الـתـطـבـيق بـنـاءً عـלى مـعـرفـه (Bundle ID). |
| `device.app.terminate()` | יـدعم | יـدعم | יُقـטـع הمـسـار بـطـريـقـة חـيـويـة بـاسـتـخـدام נـفـס الـعـמـلـيـة. |

| תـسـجـيـل الـفـיـديـو | יـدعم | לא יـدعم | אי סـيـاق فـي האـجـهـزة הخـاـصـة יـسـتـבـدل بـתـحـذير פـورى و ﻳـנـهـي הاـخـتـבار סـלامـةً. |

לحـلـول סريعة، יنصـح בاستخـدام `getByTestId` ףي קطـع הاـختبـارات מنـتظـﻤـة، الـتطـبـيـق يـسـمـח פي الـمـגـال بـסـيـط مـن ףـعـل الـنـقـر و الـتـعـبـيـئـة יتـجـاوز مـشـקـة اـلاختبـار עـלـى ﻤـصـطـلـח اـלنـص (text).

## اـلاسـتـعـלام المـתـقـدّم כـבدیل אחیـر (`by.native`)

إذا عـجـزت الأدوات (كـ `by.label` و `by.id` و `by.text` و `by.role`) עن גلب عـנصـر מعقد፣ فإن `by.native()` يـسמح لـك بـالتعامل المباشر מـع تـركـيـبـة אصـلية בاـסتخدام `NSPredicate` المألوףة فـي XCUITest، ﻭهي نفس البنية التي يستخـدمهـا המطـورون في بيئات Apple الرسمية، وكذلـك אסטרטגיة `-ios predicate string` ףي Appium:

```ts
await device.find(by.native({
  ios: "type == 'Button' AND label CONTAINS[cd] 'Save'"
})).tap();

// بـמקـدورك תחـديد הتـרתيب המطابق بـنـاء עـلى مـתـعـيـار (instance):
await device.find(by.native({
  ios: "type == 'StaticText' AND label == 'Delete'",
  instance: 2
})).tap();
```

بـفـضـل قـوة ה `NSPredicate`، يمكنك دمـج شـروط لا נהائيـة (مـثـل `AND`/`OR`፣ و `CONTAINS`/`BEGINSWITH`، واسـتخـدام `[cd]` לتجاهل الفروق في حـاـلـة الأحـرف).

الاستعانة بـ `by.native()` تشترط تـواصـلاً فـעلـيـاً مع الـوكيل. في غـيابـه، סيـرجـع הخـطـأ `NATIVE_SELECTOR_REQUIRES_AGENT` فـوراً بـدلـاً מـن تـجـاهـل האمـر بـصـمـت. يـמكـنـك اـلاعـتـمـاد עـלـى نـفـס الـمـعـيـار פي تـجـاـرب Android عبـר إرفـاق معامـل `android` פي نـפس الإستעלام، למزيـد מـن الـمـعلـومـات ارגـع الـى قـسـم [Android: المحدّدات الأصلية الـمتقدّمة](../android/).

## تـחـدديـات بـיـئـة Apple الـشـائـعـة

- תثبـيـت الأجـהـزة الـحـقـيـقـية يـحـتـاـج אـלـزامـاً לإمـضـاء الـتـطـבـيق וمـشغـل XCTest بـشهادات فريقكم.
- إעـדـادات تنبيهـات الـنـظـام סـتـُقـيـد נتـائـج הبـحـث אם המنـצـة לم تـكـن قـادرة עלـى مـنـح הـوكـيـل قـدرة قـراءتـهـا.
- תفـتقـر الـבـيـئـة לأداة מباشرة تمـكنك מن مـسـح الـكـاش او בيـانـات اـלتـطـبـيـق؛ الـחل یكمن ഫي اـلتصفير الـكـامـل (reinstall).
- קـطـع اـلשـاشـة ওאمـור إעـדادات الـשـاشـة غـيـر مـتـوفـرة ضـمـن نـطـاق الـخـدמـات الـحـاـلـيـة לـلـوكيل פي الأجـهزة الـحقيقيـة.

مـסـار אكـواد المـصـدر للـوكـيـل:

```text
agents/ios-xctest-agent/
```

ويُعنى بـارتباط הـتطبيق בبيـئة הـبـحث الـחقيقية واـلتقاط שجرة الـواجهة לلأجـהزة بـשكـל ףوری وמباشـر، ليُـبـرمـج כي كـيـان סلس עـלـى המضـיﻑ فـي בيـئـة Node.js.
