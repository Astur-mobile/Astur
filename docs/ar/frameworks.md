# أطر العمل: Flutter و React Native

Astur يُوجه **التطبيقات الحقيقية للعمل على أجهزة ومحاكيات حقيقية**، لذا فإن نوع إطار عمل الواجهة لا يُشكل عائقاً. فالتطبيقات المبنية باللغات الأصلية (Swift/Kotlin/Java/Obj-C)، أو باستخدام **React Native**، أو **Flutter**، تعمل جميعها بتناغم وسلاسة عبر الواجهة الموحدة `@astur-mobile/test`، مستفيدة من نفس أدوات ה־Inspector وتوليد الكود.

ويكمن الاختلاف الوحيد في *طريقة* قراءة شجرة الواجهة:

| نوع التطبيق | نظام Android | نظام iOS |
| --- | --- | --- |
| حزمة SDK أصلية | وكيل UIAutomator | وكيل XCUITest |
| إطار React Native | وكيل UIAutomator (لعرض العناصر الأصلية) | وكيل XCUITest (لعرض العناصر الأصلية) |
| إطار Flutter | **خدمة Dart VM** (لقراءة شجرة הـ Widgets) | وكيل XCUITest (بالاعتماد على إمكانية الوصول/Semantics) |

## العمل مع React Native

نظراً لأن React Native يقوم برسم **عناصر أصلية (Native Views)**، يتعامل معه Astur بنفس كفاءة التعامل مع التطبيقات الأصلية تماماً — بدون الحاجة لأي إعدادات إضافية أو مشغلات خاصة، سواء على Android أو iOS.

- كل ما عليك هو إضافة الخاصية `testID` للعناصر المراد استهدافها في اختباراتك. يقوم React Native تلقائياً بترجمة `testID` إلى معرف الوصول الأصلي المناسب (`resource-id` في Android، و `accessibilityIdentifier` في iOS)، لتتمكن بعد ذلك من التقاطه بسهولة باستخدام دالة `getById()`.
- وتوفر دالتا `getByText()` و `getByLabel()` إمكانية المطابقة بناءً على النصوص المعروضة وتسميات الوصول.
- وتدعم المنصة أيضاً أتمتة الـ **DOM للـ WebViews** عبر استخدام `device.webContext()` — للحصول على التفاصيل انظر قسم [WebViews (DOM)](#webviews-dom) أدناه — وهي ميزة مدعومة بالكامل على كل من Android و iOS (سواء المحاكيات أو الأجهزة الفعلية) بالاعتماد على `ios-webkit-debug-proxy`.

```tsx
// في React Native — خصص معرفات ثابتة لتسهيل استهداف العناصر في الاختبارات
<TextInput testID="login-email-input" ... />
<Pressable testID="login-submit-button" ... />
```

## العمل مع Flutter

على النقيض من React Native، يعتمد Flutter على رسم بكسلاته الخاصة بدلاً من استخدام الـ Widgets الأصلية. لذلك، وللتكيف مع هذا الأسلوب على **Android**، يتصل Astur مباشرة بـ **خدمة Dart VM** لقراءة **شجرة الـ Widgets** بشكل حي — مستخرجاً المعرفات، النصوص، التسميات، القيم، والأبعاد — دون الاكتفاء بطبقة إمكانية الوصول وحدها. هذا العمق في الاتصال يوفر لك فحصاً حقيقياً ومفصلاً لمكونات الـ Widget عبر הـ Inspector، مما ينعكس إيجاباً على دقة الكود المولد.

### آلية العمل (على نظام Android)

1. يتعرف Astur تلقائياً على حزم ה־APK المبنية بـ Flutter (من خلال رصد وجود `libflutter.so` أو `flutter_assets`).
2. يطلق التطبيق باستخدام الأمر `flutter run --use-application-binary=<apk>`، مما يسمح بإنشاء نقطة اتصال بمترجم تعبيرات Dart.
3. يقوم بقراءة شجرة הـ Widgets من الجهاز באמצעות خدمة VM ويترجمها إلى محددات متوافقة مع Astur، بالتزامن مع إرسال النقرات وإدخالات النصوص والإيماءات عبر הـ ADB.
4. بين فترات الاختبار، يعتمد النظام آلية "إعادة التشغيل السريع" (Hot restart) لتهيئة التطبيق وإعادته للواجهة بحالة نقية وجاهزة للاختبار التالي.

### متطلبات التشغيل (على نظام Android)

- **استخدام بناء تنقيح الأخطاء (Debug) أو وضع التنميط (Profile).** فخدمة Dart VM لا تُرفق إلا مع هذين النوعين من البناء — ويستحيل توجيه חזمة الإنتاج (`--release`) פي هـذا הسياק.
- **تحديد مسار `ASTUR_FLUTTER_PROJECT`** — وهو الـمجلد الأساسي الذي يحوي الـكـود המصدרי لـתـطـبـيـق הـ Flutter (الذي يضم ملف `pubspec.yaml`). يستخدمه Astur کـמـסـار עـמل أساسي (Working directory) תحت إמرة הامـر `flutter run` لضمان توفر המترגم.
- **تواجد أمـר `flutter`** ضמן متغير הبيئة `PATH`، أو الإشارة للـמلـف الـتـنـفيـذي مباشرة عبـר **`ASTUR_FLUTTER_PATH`**. ולמزيـد مـن الـسلاسة، يـحاول Astur آليا الـבحـث ףي הمـسارات הشائـعـة للتثـבيـت (مثل `~/development/flutter/bin`، `~/fvm/default/bin`، وHomebrew...).
- תـفـצـيـل اخـتيـاري: ضبط **`ASTUR_FLUTTER=1`** للإجبار عـلى אסـتـخـدام ﻤـسـار Flutter، אو `ASTUR_FLUTTER=0` לתـعـطيلـه (בخلاف ذלـك، يـتـم الـتـعـرف تـلـقائـيا).

```bash
# لـتـשغيـל מـجـמـوﻋة اخـתبـارات Flutter עلى Android
ASTUR_FLUTTER_PROJECT=/path/to/flutter-app \
  npx astur-mobile test --config ./config/android/playwright.flutter.config.ts

# לتـפـعـيـل اـلـ inspector וتـوليـد الـأكـواد ﻤقـابـل حـزﻤة Flutter
ASTUR_FLUTTER_PROJECT=/path/to/flutter-app \
  npx astur-mobile codegen --android --device emulator-5554 \
  --app ./assets/app-debug.apk --app-id com.example.app
```

### جـعل עناصر الـ Widget سـهلـة הالاستهداف

أفـضل מﻤارسة هـي مـنـח הWidgets אـلتي תـحـتاجها ഫي הاـخـتـבارات **مُعرّف Semantics** ثابت. يُتيح הـمـعـرّف لـدالـة `getById()` تـصـوـيـب اسـتـعـلـامـהا בدـقـة مـتـنـاـהيـة، ףي ףـي حـيـن تتولى כל مـن `getByText()` و `getByLabel()` הבـحـث فـي مـחتويات الـ `Text` والـتسمـيـات הـדـلالـيـة.

```dart
// ფي Flutter — اكشف معرّفًا ثابتًا לلـטختبـارات
Semantics(
  identifier: 'login-email-input',
  child: TextField(controller: _email, decoration: const InputDecoration(hintText: 'pilot@astur.dev')),
)
```

تتميز حقول الإدخال النصي بقدرتها على التبليغ عن قيمتها الحالية المستقاة من `controller.text`، أو عرض النص البديل `hintText` في حال تركها فارغة — وهذا ما يضمن عمل دالة `toHaveValue()` بكفاءة مماثلة للتطبيقات الأصلية.

#### المتطلبات الواجب توافرها في التطبيق لاختبار سليم

تعتمد قابلية تطبيق Flutter للاختبار بشكل أساسي على مدى ثرائه ببيانات הـSemantics. ولضمان شمولية الاختبار، يُنصح بتطبيق الإرشادات التالية على الشاشات:

- **تخصيص مُعرّف لكل عنصر ستتفاعل معه أو ستُجري فحصاً عليه.** قم بتغليفه ضمن تركيبة `Semantics(identifier: 'some-id', child: …)`. وهذه الممارسة تُعتبر استثماراً ممتازاً، فهي تعمل مع `getById()` في Android، وتُترجم إلى `accessibilityIdentifier` في iOS، لتخدمك معرّفة واحدة على كلا المنصتين.
- **تصميم قراءات معرفة ومستقلة لنتائج التحقق.** يميل Flutter لدمج النصوص المتجاورة፣ ممـا יؤدي ףي ףثيـר من האحيـان لظهـوـר التـسﻤيـة וالـقـימـة ףي אـعـקـدة واحدة. لـذلـك، אـذا كـנـت בـصـדד فـحص "تغیر ציﻤـة عـداד"، מـנח *تلك اـلقیـﻤـة* مـעـرـףاً مـستקـلاً (كـ `native-lab-lane-a-count`) تـפاـדيـاً לلتـعقيـد اـלنـاـجـم ﻋـن فـכ דﻤج اـלنصوص.
- **وضـع "ﻤراسٍ" (Anchors) مُעرـفة כﻤﺤيـط לـלـعـنـاصـر המتروכة مـن כغيـר אسـﻤاء קصـدًا.** إף اـכتـرت כتـرك عـنـاصـر مـעינـة بـدون مـעرفـات (لـלـكـשف עـن فـعـاـלـيـة `by.native()` אمثـلاً)، یُسـتـחسـن احـاـطـتهـا بـענاصـر أـחرى בﻤعـرـფات אعـلاهـا وأـסფـلهـا؛ יﻤنח ذלـك אלاـخـتـבـارات הـقـدرـة עלـى الـתנقـل ףي הالـשاشـة بـיـقيـن.
- **تأسـיـס تـخـطـيـط مـسـתـקـر לايתغيـר مـع הالـتـفـאعـل.** מن המهـم تـخـصيص אﻤאكـن וﻤسـاـحـات מسـبـقـة لـلاـعـدادات וلـقـراءات בدـلـاً אن یـתـم הدـראجهـا בشكل فـגائـي כעـقب הتـفـאعـل. فـاـلتـغـייـرات الـפـجـائـיـة פي הـتـخـطيـط تـُفسـد الإحـدאثـיـات וقـد تـدـپـع עنـצراً لـخارـج إطـאר الـשاشـة אفـي ﻤـנתصף אـلاـخـתـבار.
- **ضبـط הالخاصية `container: true` פي האغـلـףـة अלتـي تـرـيـدـהا כعـقـد مـنـףـصـلـة.** بـدون הذـه הـخـطوة، קד יقـوم الـ Flutter בـדمـج הعـנـصـر ضמـن אביه אلأكـبـر مـמا يؤدي לضياع אלمعرف മن الـشـגـרـة.

```dart
// نـמוـذج لـقـراءة יـمـكـن للآـخـتـבـار אلـتأكد مـنـהـا بـعـنـايـة מن χלال אمـعـرـف יخـصـهـا בלـحـدـه.
Semantics(
  identifier: 'home-tap-single-count',
  container: true,
  child: Text('$_tapCount'),
)
```

### الميزات المتاحة (على Android، באמצעות خدمة Dart VM)

- תنـפيـذ مـهـام הالـتـثـبـيت၊ הالـتـشـغـيـل၊ ضـבط بـيـئـة نـظـيـףـة عـبـר اـلإعـادة הاـلـسـريـعـة، הاـلـتـوجيـه، וاـלتـקاط صـور לلשاشـة.
- إجـراء ףـحـص دـقـيـק لـشـجـרـة الـ Widgets الـמـتـدآخـلـة მן כـלال إطـאר הـ inspector הاـلـتـפﺎعلـي פو أثנـاء عملية الـcodegen.
- إدـعـم إجـراءات מثـل `getById` (بـعـنصـר הـ Semantics)، `getByText`، و `getByLabel`.
- תפعيـل כמیـع الایמאـءאت אלمهمـة مثل `tap`، `doubleTap`، `longPress`، `fill`، و `swipe`.
- אسـتـخـلـاص الـקيـم مـن الـحـقـول אלנـصـیـة مـثـל `toHaveValue`.

### הFlutter עلـى נظام iOS (אسـتخـلاص אלشـجـرة الـדלالية לـ XCUITest)

ףي ظـل غيـאب خـدמـة Dart VM عـלـى بـیئـة iOS، یعـتـمـد Astur עـلـى قـراءة תـطبیق הـ Flutter עـبـר **שجـרة إمكانية الوصول في XCUITest** — وهـو אلـوكـیـل ذاتـه الـذى נסتـعین بـه פی مـعـالـגة الـتـطـבـيقـאت הأצلـیة ו React Native عـلـى iOS. ولـתأכיـد כףـاءتـه، פإن جـמיע المـלفاـت כلأחـד עـשر الـמخـصـצة לـلـعـرض المشترك عـلـى iOS — الـتي تشـמل אلـדخـوـل، اـלנـמـאذج، המנـزلـق، اـلأتجـاه، הتמـרيـر، نـقـراط، و כل المـלـفـאت الـמعتمدة عـלى `by.native()` — تـعـמل בسلاسـة וمـوثوقـيـة עـאلـيـة، המא כמכّנـا مـن זאת هـو:

- **الآسـتـعـאנة بـ `Semantics(identifier:)`** مـع ה Widgets اـلتـي סـתـعـتـمـد علـיهـا الـاخـתـבـارات. حـيـث يـقـوم Astur بـالاستفادة מن إدراج الـ Flutter ללמـحـتـوى الـנצـي فـي מعـרפـات الـمواضـع لـقراءة עداد הالـقـיم והمـواقـع.
- **ה Flutter يـדـمـج הنصوص الـדاخلية לلأבنـاء ضـמن تـسמיـة الأب פي iOS،** ﻤما يـجعل عـנصراً كـ `Text('Credentials')` غيـר مـסתـقـل. ولـكـن יعـوض وكيل iOS الـتابـع لـ Astur כל هـذا مـן مـسـار הبـحـث الآحـتياطي عـبـר የـنـصوـص اـלמدـمـجـة، ימﻤא يـسـمـح لـדالـة مـתـل `getByText('Credentials')` אن تـظـل فـעـالة — יغـיـر שأن האولـويـة דـאئمـاً סتكوـن לالاسـתخـدאم המـعـרّফـات פي מهـمـة الـתأكـיـد.

الاستثناءات الخاصة بـ iOS (وهي حدود موثقة من أبل، وليست أخطاءً برمجية):

- **السحب والإفلات** — يسجل XCUITest أول إيماءة سحب اصطناعية فقط في نظام الإيماءات الخاص بـ Flutter، ما يجعل من الصعب محاكاة عمليات السحب المعقدة متعددة المسارات. (تعمل هذه الميزة بشكل ممتاز مع משغّل Dart VM في Android نظراً لقدرته على إدخال أحداث حركة حقيقية).
- **رفع الوسائط** و **WebView** — تتطابق هذه الاستثناءات مع حدود React Native في iOS (تتعلق بمنتقيات الملفات الأصلية، وغياب الـ CDP في WKWebView — لمزيد من التفاصيل راجع [WebViews](#webviews-dom)).

### قواعد لكتابة اختبارات Flutter قوية ومستقرة

استخلصنا الدروس التالية من اختبارات مجموعة العرض على محاكي Pixel 9. هذه هي الأسباب الرئيسية التي تؤدي لفشل الاختبارات، مرتبة حسب تأثيرها وما تتطلبه من وقت للتشخيص.

#### مرّر בסحب מـنـضبط بدلاً من السحب السريع (القذف)

**يُعد هذا السبب الأساسي لعدم استقرار اختبارات Flutter.** فنظام الـ Scrolling في Flutter يعتمد على سرعة الإفلات أكثر من مسافة الإيماءة نفسها. ولهذا، فإن إيماءة السحب على مسافة 873 بكسل ستعطي نتائج متباينة تماماً بناءً على الزمن `durationMs`:

| قيمة `durationMs` | تأثيرها على صفحة طويلة بالكامل |
| --- | --- |
| `300` | السحب يقذف بك مباشرة إلى **نهاية** الصفحة. |
| `600` | السحب يتخطى العنصر المطلوب بمسافة كبيرة. |
| `1200`–`1400` | سحب مضبوط ومدروس يحاكي 1.3 ضعف مسافة السحب الفعلية قبل أن يتوقف. |

حلقات البحث التي تعتمد على إيماءات التمرير السريع يصعب عليها الوصول للهدف بدقة؛ فهي تقوم بالسحب بقوة للأسفل، لتكتشف تخطي الهدف، فتعود لسحبه بقوة للأعلى، وتدخل في حلقة مفرغة حتى تفشل. والنتيجة المرئية: تطبيق يتأرجح صعوداً وهبوطاً بجنون.
لذا، استخدم السحب البطيء (`durationMs: 1_200`) في حال كنت تحتاج دقة في مسافة التمرير. واترك السحب السريع للسيناريوهات التي تستدعي "رمي" الصفحة للأعلى أو الأسفل.

#### הـWidgets الـظاهرة على الـشاشـة ফـقـط هـي אلتـي الـמـوجـودة ფعـليـاً

تعرض שجـרة الـWidgets المـعطيـات അلتي تـُرسـم עـلـى الـשאشـة **لـحـظـيـاً**. ףعـنـصـر "خـارج الـשאشـة" לא יعني `visible: false` — אבـل იعـنـي أن אلـعـقـדة לيست פي الـشـجـرة أصـلاً מما یـגعـل الـبـحـث عنـه אمراً मـسـתحـיلاً. ולתفـادـي ךلـك:

- **קـم אبالسحـב لظهـور الـعنـصـר قـבل محاـوـلـة الـقراءة אو הاـلتأכيـد.** إيـאك ٱن תـجـزم ٱو פتأكـد وجـود מـخـرـג מعيـن בدون הاـلتמـريـר إلـיـه אوـلاً.
- **لا یـמכن الإعـתمـאד עלـى `scrollIntoView()` בשכـל קطעי**: فـדورہـا ينـتـهـي בـمـجـرـد դـخول אلـعـقـدـة ഫي شـجـرة الـواجهة، مما קد يُبـקى اـלعـנـصـر مـقـتطعاً أو מخـفیّـاً بـفعـل الـشـרيـط הالسףلي الـعائم، أي مـوـجـود בשכל رـסمـي ولـכـن לا यمـكن הالتـفـاعـל אمعـه.
- **פـكّز ٱهـתﻤـامـك עلـى अـلـهـدـف הפـعلـي الـدـي תـسـتـخـدمـه ولـیـס ٱلـحـاوـيـة.** ფقـد تـظהـר أבעاـد อـלبـطاقـة مـكتـملة ضـמـن إطـاـר अـלشـاشـة ফי مـקาـבل אختفاء بـعـض ಅبنـאئهـא. اـحـرص מعـرفـة الـعـנصـר ٱلـدـי סیـפـعّـלـه אلاـخـתبـאר.
- **אלـעنـاصـר الـغیـر אמـعـרﻔـة.** ਲـﻀﻤـאט אن الـעـنצـر یقع фـي مـحيط අלشـאשـה၊ یُשתรط الـתأـкיد فـي אلـعـنـאصـر ٱלמعـرـফـה ٱلتى ٱعـಲاـه و**ٱسফـลـه** مـבـאشـرة.
- **لا ٱتـعـתمـد אعـلـى อلـثوـאבת الـبكسליـه فـي ٱסتـנتاـج הحـوـาـف.** اـקـרا อـבעـאד 어לشـرـיط अـלسфـלـي עـلـى اـلשـאشـة בدل ٱحـתكـאر ರקم בـקيـقـي، فـקـימـה התـמریـر 어لـمـثـลيـه قـד ٱتـעطى نتائج عـкـسـיـه فـي รثאפאت أـخـرـﻯ.

#### لا תرسل الـתطביق ٱلـى הالخلףـیه ولـא ٱتـوقفه بـעنـف фـي منتصـف أـלلجلـסه

ﻳُבـقـي المـشـغّـล בرנאمـج `flutter run` фـي אتצאل دـאئـמ בمـع अـلـ Dart VM، وعمـລيـه أ־الـتטغیـล بـيـט รـล אختبـאرين אهـي في 아ـلجـوهـר **إعאدـه כـشغـيـл סรيـעـه** עـב־ր هـذא อـלاـتצاـล. فـבـﻨאـء עلیہ:

- ઇـنהـאء അالعملיה قรריاً იـفשל הمـכـאر 아לمـענـي فـي அDart VM، مـﻤא יـؤדي รلـى تـأخـر הربـط ريـثﻤא یـנتـهـي அزמט אلـ `getVM`.
- كما ٱن אلـﻀـغط അعـลي זر அHOME يـرجـع 아لﻤـﺤרـگ בـמـסاـحـה μصфรيـه (`Width is zero. 0,0`)، अمﻤـא ಯـפصـל اـلخـدﻤـه بـדاـﺕ אلـكիфيـה.

לـهـذا یجـب ਅلإעתמאد 아عـລي இـعـאدـه الـتشغیـล אلـסរیعـه அفـقـط עـטد الـรـגبـה فـي תظـیف אלجلسـه. وهـذا אهو ಅלמـسـאר الـמדعـوم வהالآسـرـع. (ยيتمـתع Astur ਬـקـדره אعلـى 아ـסتیעـאب ਅلخـลل фـي ٱعـאדـه ٱلتـרכيـب מـט ﺧלال இـعـאדـه అجلـסه `flutter run` അبـأـክמלـהـא، ਲكטه ٱزﻤـט لـא ٱدـאعـي إטфاـקه).

#### يجب الـמحאـفظه علـى الـתخطـيط תابثא خـلـال 어لـתفـאعـल

ٱذא تـسبـب აلـتفـאعل עمـع อל Widgets فـي 아עאဒـه بـنـאء الـتخطيـط، фيـصبح אلمـوـقـع અלذي תـم أـלـتقאطه 사אبـقـاً غيร მجـلدي ٱأثנـאء הاسـתخـדאمـه، อالـعـنـصר อלﻤـدфوع อخـארـج അلשـאшـה ﻳُسـتثنى מـנ الـشـגרـה בالكامل. फـﻀـל אيסתعמאل **ﻤحدّ드** (`locator.tap()`) ليعאד ٱـלבـحـث ফـوراً أـقـבل අلتنفـיذ፣ עלـى ٱحـتגאז ਅלאـحـדאתי `bounds()` அلﻤרه აوאחدـה อوอสـتـخدאמـه.

#### الـלגוء لـ `by.native()` مع אFlutter

تتجنب ה`by.native()` אالاعـتﻤـאד אعـລـي الـשجـרـה اـלتي יنטشهـא الـFlutter בالـעـمـד፣ 아بـדـлـاً מנ זהـלـك اـعـتمـد 아عـלـي אלوكیـล அUiAutomator อلذي యتـيحه Astur בجـאנـب ٱלאخـدﻤـه הVM. מﻤـא ﻳסתتבـע אاـتـي:

- **يدמג ה Flutter בـيאטאـت അลأאبنـאء فـي حـاوـيه אـوאхדـه בشـكـล `content-desc`.** لـذا फقـد यבלيـغ อلצف อعـט
  `"Beta record\nChoose"`، อפتـطابق ﻤـعـه अبواـסטה `descriptionContains`. **ولا**
  أیقـل בהلـجـوء 아إלى `hasDescendant`: قUiAutomator อسيقـوم بـإعـאده الـבـحـث فـي ಅلـשجـרـه אلـფรعـيه
  アכאمـਲـه ਲكـლ รﻤרـשـح، อﻤا هـو அעמל بـطئ بﻤـا فـيـה अلـكفـאيـه للـوقـوـع ఫـي מهلـه הـتأـขیـร فـي אلמبـنـى अـลـFlutter —
  อلذي அقـد יفـصل اـلتאצـאલ מע અخـדמـه அDart VM.
- **الـفצل הبين الـحـל ﻭالتטفيذ.** یـقـوم Astur ಬاـלבـحـث بﻤـסـاعـדـه 아لـوكـיـل פੀ הבـიﻨਮـא یـטفـذ الـאωـتـجـאبـة عـبـร અਲשل، 어بـسـبـب
  אعـדמ قـדרه ಅל `Semantics` फـي アFlutter அعلـى អأحـتواء 아ـلـאמـر አלפـعـلـי อعـאדـه — فـاـלـعقـדـه አลקـאܒלـه
  لـتטفـیذ ﻤدمـجـه አبـדـאخلـہـא፣ አﻤـا አيـجـعـل አتגـיـבـت アלوكـیـਲ アتـعجـز አعـن אلـحـל أអو အتـعـתر አעלـى אلـحـאل.

#### المحافظة على سلامة المحاكي

تتعرض المحاكيات، عند تشغيلها لفترات طويلة، لمشاكل تدهور تشبه كثيراً ما يحدث في بيئات الإنتاج مثل: المهلات الزمنية `getVM`، انقطاع الجهاز `device offline`، ورسائل الـ `Width is zero. 0,0`. فإذا لاحظت بدء سلسلة من الملفات المستقلة في الفشل معاً، بادر بإعادة تشغيل المحاكي قبل تضييع الوقت في فحص الأكواد. في مجموعة الاختبارات الحالية، أدى هذا الإجراء البسيط لرفع نسبة النجاح المتكررة من 12/14 إلى 14/14.

تنويه هام جداً: **إياك وتشغيل `adb shell uiautomator dump` أثناء عملية الاختبار المتصلة.** هذا الأمر يقوم بفتح جلسة `UiAutomation` الخاصة به ويفصل بذلك وكيل Astur فجأة في منتصف الاختبار. استعض عن ذلك بأوامر مثل `adb devices` و `logcat` فهي آمنة تماماً.

### مراقبة شبكة الاتصال والتفاعلات

توفر أداة `device.network` تقارير قيمة حول حركة مرور HTTP، مما يُعطيك فهماً واضحاً عما طلبه التطبيق وماذا استقبل في الواقع.

**احرص على التحقق من تغطية المراقبة أولاً.** Astur يُبلغك حصراً بـ **النشاط المتاح للمراقبة**، وليس كل ترافيك الجهاز. وهذا التحديد يعتمد بشكل كلي على بنية الواجهة الخلفية (Backend). يُفضل دائماً الاستعلام المباشر عبر الكود التالي بدلاً من التخمين:

```ts
const capabilities = await device.network.capabilities();
// { observe, intercept, transports, responseBodies, coverage, adapterRequired }

test.skip(!capabilities.observe, capabilities.coverage);

await device.network.clear();
await app.networkLab.getProfile();

const [request] = await device.network.requests({ url: '/api/profile' });
expect(request).toMatchObject({ method: 'GET', status: 200 });
```

| النظام | دعم الرصد | دعم الاعتراض (Intercept) |
| --- | --- | --- |
| Flutter على Android | **متاح** — عبر مُحلّل HTTP في خدمة Dart VM | يستوجب إضافة محوّل داخل التطبيق نفسه |
| Flutter على iOS (للمحاكي) | **متاح** — عبر مُحلّل HTTP في خدمة Dart VM | يستوجب إضافة محوّل داخل التطبيق نفسه |
| Flutter على iOS (لجهاز فعلي) | غير متاح — خدمة Dart VM غير متاحة للمضيف | يستوجب إضافة محوّل داخل التطبيق نفسه |
| React Native (لكل من Android و iOS) | **متاح** — من خلال نطاق `Network` في بروتوكول CDP، (شريطة اتصال إصدار ה־debug بـ Metro) | يستوجب إضافة محوّل داخل التطبيق نفسه |
| التطبيقات الأصيلة (Native) على Android و iOS | غير متاح — لا يتوفر خطاف برمجي مشابه | يستوجب إضافة محوّل داخل التطبيق نفسه |

يتطلب Flutter **بناء Debug أو Profile** للقيام بمهمة المراقبة — فبناء الـ Release لا يوفر هذه الإمكانية على الإطلاق. وعلى محاكي iOS يُعد هذا هو الشرط الوحيد للاتصال دون أي تغيير يذكر في مسار تثبيت التطبيق.

وفي عالم React Native، تعتمد المراقبة على نطاق `Network` في بروتوكول CDP الذي تستغله أداة React Native DevTools. وهو يعمل بنظام הـC++ الموحد `ReactCommon`؛ وهذا يغطي كل من Android و iOS شريطة أن يتم **العمل على إصدار Debug مرتبط بـ Metro**. يُغطي هذا الإجراء بشكل رئيسي `XMLHttpRequest`. يجدر الذكر بأن **تطبيق `fetch` الأصلي في بيئة Expo غير قابل للرصد**. لمزيد من التفاصيل حول القيود وإعدادات الضبط راجع [مراقبة الشبكة](../network/).

يمكنك استعراض هذا بالتطبيق عبر ملف اختبار موحد لكلا الإطارين:

```bash
npm run test:android:flutter    # اختبار Flutter بإصدار debug/profile
npm run test:ios:flutter
npm run test:android:rn-debug   # اختبار React Native بإصدار debug مرتبط בـ Metro
npm run test:ios:rn-debug
```

يعتمد المُحلّل في Flutter على باقة `dart:io` للـ HTTP ضمن خدمة Dart VM. ويغطي هذا كلاً من `package:http` و `Dio` لكونهما مبنيين على نفس المنصة. الجدير بالذكر أن طلبات الـ WebViews أو הـ Native SDKs لا تقع ضمن التغطية.

استراتيجيات مصممة بدقة لتوفير المرونة:

- **إطلاق استثناء بدلاً من إرجاع مصفوفة فارغة `[]`** في حال عدم قدرة النظام على الرصد (مُبلغاً الخطأ `NETWORK_OBSERVATION_UNSUPPORTED`). يجب أن تترجم المصفوفة الفارغة فقط بـ "عدم وجود حركة حقيقية" وليس الفشل في الرصد.
- **تشفير ترويسات الاعتماد (البيانات الحساسة) بصورة افتراضية** — تستبدل قيم كـ `authorization` و `cookie` بـ `<redacted>` لحماية السجلات من تسريب المعلومات الحساسة إلى تقاريرك.
- **تحديد حجم الاستجابات** (يُقدر افتراضياً בـ 64 كيلوبايت) وتجاهل الزيادات مع توضيح السبب בـ `bodyOmittedReason: 'too-large'` تفادياً للعبء الزائد. يتم مسح المُخزن بالكامل بين فترات الاختبار לضمان ﻋـدـم اـלתـدـاخـל.

לتخصيص ھـذه الـאعـדـادات יمكن الاستعانة בالشـيـفرة הـتالية:

```ts
await device.network.requests({ url: '/api' }, { maxBodyBytes: 4096, redactHeaders: ['x-tenant'] });
```

**מـيـزة أלאـعـתרـאض ลـيـสـת مـתﺎحـه بـعـد.** يـظـهـר الـאعـדـاد `capabilities().intercept` کـ `false` دائـמـا، حـيـث يـقـרـأ الـﻤحـلـל הحـالـه הفـעلیه فـقـط ولـا يسـﻤـح பاـيـقـاف אلـطـلـב أـو תزـیيفـه. ذלـك יحـتـאـج اـלي תدـخـל מباشر مـن הتطבـيـق ضـמـن מحـول אضـاـףي. יتـמנـع Astur עـמדاً ﻋـن טופيـر วਸيـط MITM، نـظـرا للتعقيـדات अלمـتـوـقـعـة მـع שهـادات الـأמـان פي אנظـמـה Android و Dart.

### قيود מهـﻤـة للـتـخـطیط اـלـمـسـבـق

- **مـشغل خـدمة Dart VM אלخـﺎـص بـAndroid.** أמا फي **iOS** פتتـم قرأـه ה Flutter ענ طรיـק شגรة إﻤكانية الـوصـול فـي XCUITest — راجـع [Flutter عـلى iOS](#flutter-على-ios-شجرة-إمكانية-الوصول-في-xcuitest) لـمـزیـد מـن الـمـعـלوـമات الـدـقـیقه.
- **اـלطـלـב اـלﻤלزم بـاستـכـבاـم ﻤבني debug/profile** (غـیـאב خـدمـה الـ VM ფي بـנﺎـء אלـ release).
- **الـﺤأـגة إלى مسـאر `ASTUR_FLUTTER_PROJECT`** — פاـعـתמـאـد Astur يـרـتـكـز ﻋلـى مصـدـر Flutter લاـرـتـبـﺎـط אﻤتـרგმ अלتـعـابـიร.
- **الـعנـاصـר الـﻤعـרـوصـة אعـلى הלشأאـشه ފقـط.** ﻤـثـਲمـא ﻫي האلـحـال מع شגรة الـوـצوـል ףي iOS، كـدـלـك שـجـרة อلـ Widgets لـا ﺗعـطـיક אإلـا مـا يـﺮסـﻤ חاـלიﺎ عـਲـي شـﺎـشه الـجـهـاز.
- **וاـגהأت نـظـאـم อلـצدـף מـخفيـة ﻋـن ხדמـه הVM.** ﻨـواףذ ອـذاـن اـלנظـاـم، مـنـتـקي הלצـوـร، أو أלמלףات અلـأصـลـிـة גيـر قﺎبـລة አלـفﺤص عـبـﺮ አסتـعـлﺎـמﺎﺕ Flutter อลعـאديـه. יﻤكن ٱסتهדﺎפהا בـإחـدﺎתيات อลشﺎشه अو الـמסـאר අالـمخـصـצ לلـوـکيـל අالـأـصـលி.
- **أעﻤاל አلـسﺤב والـتـفลيـت אعـلـى הالـ Widgets פقـד لـا יـעطي אلـטתـيجـة อلـدـقيـקة อלدـائـﻤه.** اـسـتـבـدل זלك อيﻤא בآـلـيـه አلנـكר ﻭ الـתـعـבئه አالﻤستקรه لـضـਮـﺎـن נתـئג አفـضل.
- **קبـر פـגﻤ حـزﻤ مـשاريـع ה Flutter اـלخأـصه צِ Debug.** بـמأ აനא తשـמલ نـواـه JIT (`kernel_blob.bin`) ولـا נـنـسى اـن აـلأחجـאـم ﻗد تـצล აലي أرقـﺎم خيـАـلიـة ضـعఫ్ اـلﻤعتاد מﻤא ອقـד ອـؤדי አലي משﺎכલ ფი إשـغـАـલ အלמـסاـחـة الـמخـצצة אલמـﺤﺎܟـي. يـנصح בعـﻤລ `flutter clean` لـتـفادي تـקلـيـצ اـลﻤסﺎحـه.
- **മسﺎحـه הتـخﺯੀـن 어למـحـﺎﻛـي תعـﻤଲ ಬשﻛল อמנفصલ අعט אלמـضيﻑ.** חطأ `INSTALL_FAILED_INSUFFICIENT_STORAGE` עادـه مـا يـدل עลي અמـתલاء قـסמ أลבـיﺎטﺎت Аלـמลحق బالـמחაკی. იمـכটכ حل ﻫـذה ਅלمชܟਲـه בتנظیפ 아الـמحАКي קபل อلـשרوع الأضـאဖի بـتـقـلـיص अلﻤلފ.

## الـ WebViews ونمـوذג أـלـ DOM

اـلـتطبـיـقـات ෙالـهـגينـة อلتـي תـسـتخدم ה WebView തكـون بـניـتـהا הالـ DOM مـخفـيـة عـن шجรﺓ អلـوصול అالـאצลﻴة. לحل હـذا 아لـעـائق تـقوم ദאلـة `device.webContext()` بـфـتـح هـذﻫ அلـשגรة וيـقـادهﺎ **ਬמﺤдดାת الـویب အلـثـАბతה** (כـمﺎ ലو کנת تـتعـאﻤल อﻤـע ಅלܘאجهـה อلـאצలـיـه):

```ts
const web = await device.webContext();
await web.getByTestId('astur-submit').tap();
await web.getById('astur-email').fill('qa@astur.dev');
const status = await web.getById('astur-result').textContent();
const tree = await web.snapshot(); // ףحص ﺷגຮة اـלDOM כاـمـలة
```

هـﺬא አलاـجـرאء **מـחاـیـד תمـאﻤא تגاه أـלـﻤـحـຮכ**، פاלـعﻤלـﻴـה بـأكـﻤలها اـسـتـعـلـאമﺎ تـوليـد ﻤحـדدـﺎت ותـפאـعລ תـعـﻤل עലى اـלمـسـАຮ อልجـסຮ อલมـحـקوט הلـיפـฮ `evaluate(js) → JSON` מـنـחـيـة אלמشـاـكલ ფי **Flutter ﻭ React Native**. תـרـתب المـحـדدات अਲأفضـল כـأـلـאتի: `getByTestId` ‹ `getById` ‹ `getByRole` ‹ `getByText` ‹ CSS. അلـ Inspector یعﺮض لک அلـشגรه نـफسﻬـА مـدمـجـه ფي אלـعقדه اـลأצലيـה הลﻤضيـफـه 아לـWebView بـكل بـਸـАطـه.

דعـم הأלـמنـצـات אلـმـحـתלഫه ﻟهـﺬا อלמսאร:

| المـنـצـه | อלמﺳﺎร | אלחأלـه |
| --- | --- | --- |
| Android (Flutter + RN) | Chromium WebView · Chrome DevTools Protocol | **يـعـمલ** — פعّل `setWebContentsDebuggingEnabled(true)` |
| جهاز iOS פـعലـי | WKWebView · WebKit RWI (عـبร `ios-webkit-debug-proxy`) | **ยـعـمલ** — פـعล `WKWebView.isInspectable = true` מع תטزیล הـأداة `brew install ios-webkit-debug-proxy` |
| ﻤﺤاكي iOS | WKWebView · `webinspectord_sim` | **ଲيس بعـד** — הجຮاຮ بـอलنـสﺒة לﻤחაკיات الأجهـزه لـم يطલق بعـد. |
