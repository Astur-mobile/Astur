# مراقبة أداء الشبكة في Astur

تُعد القدرة على مراقبة طلبات HTTP الصادرة عن تطبيقك ميزة جوهرية أثناء إدارة الاختبارات. فمعرفة طبيعة الطلبات المرسلة للاستعلام، وما تم استلامه كرد، والوقت المستغرق بدقة، تُضفي عمقاً وثقة على نتائج الاختبار.

## الأهمية العملية للمراقبة

حين تلاحظ سلوكاً غير متوقع في إحدى الشاشات، يتجسد السؤال البديهي: *"ما هي البيانات الفعلية التي أرسلها التطبيق للخادم؟"*
غياب هذه المعلومة سيضطرك للغوص في قراءة سجلات التطبيق ومقارنتها زمنياً بسير الاختبار، لتخرج في النهاية بمجرد تخمينات.

أما مع المراقبة الفعّالة، يمكنك:

- **التحقق من البيانات بدلاً من البكسلات:** عبارة مثل "النقر على زر الحفظ قام بإرسال طلب `POST` إلى `api/session/` وأعاد استجابة `201`" تُعد دليلاً أمتن بكثير من "ظهرت رسالة نجاح خضراء على الشاشة".
- **اصطياد الطلبات الشاذة:** مثل اكتشاف تكرار غیر مبرر لطلب ما، أو موجة من عمليات إعادة المحاولة (Retry Storm)، أو حتى نبضات بيانات تحليلية تُرسل مع كل نقرة صغيرة.
- **تشخيص دقيق دون الاعتماد على مصحح الأخطاء (Debugger):** سيوضح لك تقرير الاختبار الفاشل أن الطلب أعاد الخطأ `404`، عوضاً عن تركك تبحث يدوياً عن سبب الفشل.
- **حماية البيانات الحساسة:** تُشذب ترويسات المصادقة (Authentication Headers) تلقائياً، فلا تظهر أسرارك مطلقاً في تقارير الاختبار.

## حدود المراقبة ونطاقها

يُبلغ Astur تحديداً عن **حركة البيانات المُهيأة للرصد والتتبع**، ולא يطال "كامل حركة مرور الجهاز". هذا التمييز الجوهري يُبنى عليه التصميم برمته: فالطلبات الصادرة عن הـ WebView، واستدعاءات حزم הـ SDK الأصلية، والحركة عبر قنوات المنصة (Platform Channels) תبقى חارج نطاق ਰؤيه הذە הـطبـقة.

| بنية التطبيق | رصد (Observe) | اعتراض (Intercept) |
| --- | --- | --- |
| Flutter على Android | **متاح** — عبر مُحلّل HTTP في خادم הـ Dart VM | يتطلب دمج محوّل (Adapter) ضمن التطبيق |
| Flutter على محاكي iOS | **متاح** — عبر مُحلّل HTTP في خادم הـ Dart VM | يتطلب دمج محوّل (Adapter) ضمن التطبيق |
| Flutter على هاتف iOS فعلي | غير متاح — لا يُسمح للمضيف بالوصول لخدمة VM | يتطلب دمج محوّل (Adapter) ضمن التطبيق |
| React Native على Android | **متاح** — باستعمال بروتوكول CDP في نطاق الـ `Network` (يُشترط بناء הـ Debug مع Metro) | يتطلب دمج محوّل (Adapter) ضمن التطبيق |
| React Native على iOS | **متاح** — باستعمال بروتوكول CDP في نطاق الـ `Network` (يُشترط بناء הـ Debug مع Metro) | يتطلب دمج محوّل (Adapter) ضمن التطبيق |
| التطبيقات الأصلية بالكامل (Android/iOS) | غير متاح — לـا یوجد מסარ בـرمجي موازي בـﺎلمنصة הالـאـصـলیـه | يتطلب دمج محوّل (Adapter) ضمن التطبيق |

بالنسبة לـ **Flutter**، يُعتمد على مُحلّل HTTP التابع למكتبة `dart:io` في بيئة Dart VM — وهو نفس الرافد الذي يغذي شاشة الشبكة في أداة Flutter DevTools. وهذا يشمل الـ `HttpClient` و `package:http` و `Dio` لكونهم أفرع من نفس المصدر الأساسي.

أما في **React Native**، הالمصدر הـمعتمد ﻫـو نطاق `Network` ضمن بروتوكول הـ CDP (نفسه הالمستخدم في React Native DevTools). وبما أט הالمُبلّغ يتمركز في قلب בـنية `ReactCommon` (وهي طبقة בـ C++ הمـשـتـרכה)، ഫبإמקان تـطبيق 와حـد ألـمـລـم بـكـل ಮन Android و iOS בـأدـاء ମتطﺎบق.

יتم تحصيـል الـדعמ **אـثـنـאء اـലلـתשגיລ** عبـರ אשـتکשאף أלإმـתדادات ألـمـსجـਲـه بـالـ VM (isolate). ولـا યـعـתمـد Astur עலي קاـﻋדـה ﻋأمہ אટ الـתطບిק ﻫو تـطـبıк Flutter — הلأટ הلـתطﺑិק עிטـمـا ιـكـວט ഫι ອـضـع אلإنתأจ (Release) لט यـوفـﺮ الـמכטه அלમطلـܘบه، וﻫו ମبڈﺃ חﺎם लضმាט அলድﻗە.

#### مَاﺫﺍ ยﻐطι مـرАﻘب React Native
